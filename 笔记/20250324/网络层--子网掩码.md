### 1.局域网的私有IP地址

+ 指在局域网内部使用，不会在公网上出现的IP地址。被保留用于私有网络，避免与公网IP冲突
  - **A 类私有地址**：10.0.0.0 - 10.255.255.255，掩码为 255.0.0.0。这个地址段可以提供大量的主机地址，适用于大型局域网
  - **B 类私有地址**：172.16.0.0 - 172.31.255.255，掩码为 255.240.0.0。该地址段可容纳中等规模的局域网
  - **C 类私有地址**：192.168.0.0 - 192.168.255.255，掩码为 255.255.255.0。这是最常用的私有地址段，适合小型办公室、家庭网络等。

+ 私有IP地址不能直接在互联网进行通信，如需要访问互联网，通常需要通过网络地址转换技术将私有IP地址转换为公网IP地址

### 2.本机环回地址（Loopback Address）

+ 一种特殊的IP地址，用于计算机自身的测试和通信

  - **地址范围**：在 IPv4 中，本机环回地址通常是`127.0.0.1`，子网掩码为`255.0.0.0`。在 IPv6 中，对应的环回地址是`::1`

  - **作用原理**：当应用程序使用环回地址发送数据时，数据并不会真正发送到网络上，而是在本地计算机内部进行循环，直接从网络层的发送缓冲区回到接收缓冲区，仿佛是从外部网络接收数据一样。这样可以方便开发人员测试网络应用程序，而无需依赖实际的网络连接

  - **使用场景**：主要用于本地网络服务的测试和调试。例如，在开发 Web 应用程序时，可以在本地计算机上搭建 Web 服务器，并通过环回地址访问该服务器，以检查应用程序的功能是否正常。此外，一些数据库管理系统、邮件服务器等在本地安装和配置后，也可以使用环回地址进行本地连接测试

### 3.特殊地址

+ `255.255.255.255`：是一个广播地址，称为受限广播地址。当一台主机向这个地址发送数据包时，数据包会被发送到本地网络中的所有设备，而不会被路由器转发到其他网络。它常用于在本地网络中进行广播通信，例如在网络启动时，设备可能会使用受限广播地址来发送请求，以获取网络配置信息。

+ `0.0.0.0`：在网络配置中，它通常表示 “任何地址” 或 “不确定的地址”。例如，当一台计算机在启动过程中还没有获取到有效的 IP 地址时，它可能会使用 0.0.0.0 作为源地址来发送 DHCP 请求，以请求从 DHCP 服务器获取一个合法的 IP 地址。此外，0.0.0.0 可以用来表示监听所有可用的网络接口，即该服务将接受来自任何网络接口的连接请求

### 4.应用层常见协议

+ **HTTP（超文本传输协议）**

    - 功能：用于在网络上传输超文本数据，是互联网上信息传递与共享的基础协议

    - 工作原理：客户端（如浏览器）向服务器发送请求，服务器根据请求返回相应的资源，如 HTML 页面、图片、视频等。请求和响应消息都包含特定的格式和头部信息，用于传递请求方法、资源路径、状态码等信息

    - 特点：简单快速、灵活可扩展，但数据以明文传输，存在安全风险。

- **HTTPS（超文本传输安全协议）**
  - 功能：是 HTTP 的安全版本，通过在 HTTP 基础上加入 SSL/TLS 协议来实现加密传输和身份验证，确保数据在传输过程中的保密性和完整性
  - 工作原理：在建立连接时，客户端和服务器先进行 SSL/TLS 握手，协商加密算法和密钥等参数。之后，双方使用协商好的密钥对传输的数据进行加密和解密
  - 特点：安全性高，可防止数据被窃取、篡改和监听，但会增加一定的性能开销，因为加密和解密数据需要消耗额外的计算资源
- **SMTP（简单邮件传输协议）**
  - 功能：主要用于发送电子邮件，负责将邮件从发件人的邮件服务器传输到收件人的邮件服务器
  - 工作原理：发件人通过邮件客户端将邮件发送到自己的邮件服务器，发件方邮件服务器根据收件人地址，通过 SMTP 协议与收件方邮件服务器进行通信，将邮件传递到收件方服务器。收件人可以通过邮件客户端从收件方服务器获取邮件
  - 特点：简单可靠，广泛应用于电子邮件系统，但它只负责邮件的发送，不涉及邮件的接收和管理
- **POP3（邮局协议版本 3）**
  - 功能：用于接收电子邮件，允许用户从邮件服务器上下载邮件到本地计算机或设备
  - 工作原理：用户使用邮件客户端连接到邮件服务器的 POP3 服务，通过用户名和密码进行身份验证。验证成功后，客户端可以请求下载邮件，服务器将邮件发送给客户端，并根据客户端的指令删除或保留服务器上的邮件副本
  - 特点：使用方便，能让用户在本地管理邮件，但它在下载邮件后通常会将邮件从服务器删除，不利于在多设备间同步邮件
- **FTP（文件传输协议）**
  - 功能：用于在网络上进行文件传输，支持客户端与服务器之间上传和下载文件
  - 工作原理：客户端与 FTP 服务器建立连接后，通过用户名和密码进行身份验证。然后，客户端可以使用 FTP 命令进行文件操作，如列出目录、上传文件、下载文件等。服务器根据客户端的请求执行相应的操作，并将结果返回给客户端
  - 特点：传输效率高，能快速上传和下载大文件，但 FTP 的安全性相对较低，用户名和密码以及传输的数据通常以明文形式传输，容易被窃取

### 5.传输层的两个常见协议：TCP/UDP

#### 1.TCP

+ 特点
  + 面向连接：在进行数据传输之前，TCP 需要通过 “三次握手” 建立连接，确保通信双方都做好了数据传输的准备。传输结束后，再通过 “四次挥手” 关闭连接
  + 可靠传输：TCP 采用了确认机制、重传机制和滑动窗口机制等，确保数据能够准确无误、按序到达接收端。如果发送方发送的数据没有收到接收方的确认，就会重新发送该数据
  + 拥塞控制：TCP 能够根据网络的拥塞情况动态调整发送数据的速率，避免网络拥塞。当网络拥塞时，TCP 会降低发送速率；当网络状况改善时，再逐渐提高发送速率
  + 字节流传输：TCP 将应用层的数据看作是无结构的字节流进行传输，接收方需要根据应用层的协议来解析这些字节流
+ 应用场景：适用于对数据准确性要求较高、对传输效率要求相对较低的场景，如网页浏览（HTTP 协议基于 TCP）、文件传输（FTP 协议基于 TCP）、电子邮件（SMTP、POP3、IMAP 协议基于 TCP）等

#### 2.UDP

+ 特点

  + 无连接：UDP 在传输数据之前不需要建立连接，发送方直接将数据报发送给接收方，接收方收到数据报后也不需要发送确认信息

  + 不可靠传输：UDP 不保证数据的可靠传输，也不保证数据的顺序性和完整性。如果数据在传输过程中丢失或损坏，UDP 不会进行重传
  + 高效性：由于 UDP 不需要建立连接和进行复杂的确认机制，因此具有传输速度快、开销小的特点
  + 数据报传输：UDP 将应用层的数据封装成一个个独立的数据报进行传输，每个数据报都有自己的首部和数据部分

+ 应用场景：适用于对实时性要求较高、对少量数据丢失不太敏感的场景，如在线视频、音频流、实时游戏、网络电话（VoIP）等
